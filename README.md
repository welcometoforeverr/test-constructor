# CulinaryLab — система учета кулинарных экспериментов

Сквозной учебный проект Калугина Никиты Александровича, ЭФБО-12-24.
Дисциплина: «Технологии разработки приложений на базе фреймворков».
ПР1–ПР7 сохранены; ПР9 переводит сайт и консоль на Django ORM.

## Возможности

- Каталог рецептов: поиск по названию, фильтр категории, число опытов и средняя оценка.
- Журнал экспериментов: поиск по описанию, рецепту или автору; фильтры оценки,
  рецепта, даты и отмены; четыре варианта сортировки; по 5 записей на странице.
- При переходе по страницам сохраняются все GET-параметры. Неверные значения
  формы показывают ошибку; корректные фильтры продолжают работать.
- Главная, карточки рецепта и эксперимента, статистика категорий и результатов.
- Консоль создаёт рецепты и эксперименты и отменяет опыты. Изменения сразу
  видны на сайте. Действия консоли и набор страниц предыдущих работ сохранены.

## Установка и первый запуск в Windows

Python 3.11 или новее, Django 5.2, SQLite, pytest, pytest-django, flake8.

```powershell
git clone https://github.com/welcometoforeverr/test-constructor.git
cd test-constructor
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py import_legacy
python manage.py check
python manage.py runserver
```

Открыть http://127.0.0.1:8000/. В другом терминале с тем же окружением:
`python main.py`. Создание и изменение записей из браузера не добавлялось:
существующая консоль остаётся интерфейсом ввода данных.

## Переход с ПР7 и сохранение данных

Выбрана отдельная база с чистыми миграциями и переносом данных:

- `data/culinary_lab.sqlite` — сохранённый в Git снимок ПР7, только источник переноса.
- `data/culinary_orm.sqlite3` — общая рабочая база Django и консоли, исключена из Git.
- `CULINARY_DB_PATH` задаёт другой путь рабочей ORM-базы для обоих процессов.
- `db.sqlite3` от ранних версий сайта больше не используется.

Если продолжаете локальную копию с собственными данными, сначала остановите
старую консоль и сервер, сделайте копию своей базы ПР7. После обновления кода:

```powershell
python manage.py migrate
python manage.py import_legacy --source "C:\путь\к\копии\culinary_lab.sqlite"
```

Команда читает источник в режиме `mode=ro`, проверяет целостность, переносит
4 таблицы в транзакции, сохраняет первичные и внешние ключи, сравнивает количества.
При ошибке перенос полностью откатывается. Непустая целевая база и совпадение
путей запрещены. Для повторного запуска сайта импорт не нужен.
Проверенный снимок содержит 1 пользователя, 2 рецепта, 1 эксперимент, 1 результат.

SQL-файлы, `db/database.py`, `db/queries.py`, `db/bootstrap.py`, `db/import_json.py`
сохранены как реализация ПР7 и проверяются прежними тестами. Сайт и консоль
их больше не используют. Команда `python -m db.import_json` относится к ПР7
и пересоздаёт старый снимок из JSON; для ПР9 используйте `import_legacy`.
Прямое чтение sqlite3 осталось в переносе и независимых проверках старого слоя.

## Модели и миграции

| Модель | Основные поля и ограничения |
| --- | --- |
| `web_recipes.Recipe` | ID, name от 3 символов, category |
| `web_experiments.User` | ID, name, уникальный EmailField email; участник предметной области, отдельно от django.contrib.auth |
| `Experiment` | ID, user, recipe, change_description, положительные temperature и duration_minutes, DateField experiment_date, is_cancelled=False |
| `ExperimentResult` | ID, experiment, taste_score от 1 до 10, status |

`Experiment.user` и `.recipe` — ForeignKey с `PROTECT` и обратной связью
`experiments`: участник и рецепт с историей не удаляются. `ExperimentResult.experiment`
— OneToOneField с `CASCADE` и обратным именем `result`: удаление опыта удаляет
только его результат. Положительные значения и диапазон оценки закреплены
CheckConstraint в базе; перед записью через консоль и импорт выполняется full_clean().
Миграции: `web_recipes/0001_initial`, `web_experiments/0001_initial`.

## ПР10 — административная панель и ORM

После `python manage.py migrate` создайте локальную административную учётную
запись: `python manage.py createsuperuser`. Адрес панели: /admin/.
Участник кулинарного эксперимента — прикладная модель User, а не учётная запись
Django. Зарегистрированы Recipe, User, Experiment и ExperimentResult. Настроены
столбцы, поиск по связанным полям, фильтры, сортировка и inline-объекты.
Recipe имеет стабильный slug и get_absolute_url(); старые адреса по ID сохранены.
ExperimentQuerySet предоставляет active(), cancelled(), completed(), for_date()
и with_details() (select_related). Статусы результата используют TextChoices
без изменения прежних значений. Завершённый опыт — неотменённый опыт с результатом.
В кулинарной предметной области нет бронирования ресурсов: несколько опытов
одного рецепта в один день разрешены.

Для анализа SQL включите Debug Toolbar локально (PowerShell):
`$env:CULINARY_DEBUG_TOOLBAR="1"`, затем `python manage.py runserver`.
На странице списка откройте вкладку SQL. В обычном режиме панель выключена.

## ПР11 — формы Django

На страницах рецептов и экспериментов добавлены ссылки создания и редактирования.
ExperimentFilterForm (GET) проверяет параметры поиска. RecipeForm и ExperimentForm
(ModelForm) проверяют ввод на сервере; результат опыта записывается вместе с опытом
в одной транзакции. Оценка должна быть от 1 до 10, температура и время — положительными,
описание — непустым, дата проведённого опыта — не в будущем. Отменённые записи
не редактируются; отмена выполняется только POST с CSRF. Повторные опыты одного
рецепта разрешены, в отличие от бронирования помещений в примере Roomly.
Рецепты поддерживают загрузку JPEG, PNG, WebP до 5 МБ (Pillow).
Файлы хранятся в media/recipes/; MEDIA_URL и MEDIA_ROOT настроены.
Для локального учебного приложения формы доступны без регистрации; админ-панель
требует административную учётную запись. Для публичного развёртывания потребуются
аутентификация и разграничение прав на пользовательских формах.

После обновления установите зависимости и примените миграции:
`python -m pip install -r requirements.txt`, `python manage.py migrate`.
Существующую ORM-базу не пересоздавайте и не импортируйте повторно.
